# PROITBRIDGE Success Stories Proposal

Content, visual design and motion for review

16 November 2026

This proposal responds to the revised Success Stories document and the manager’s feedback. It is a review deliverable, not an implemented website. The working code folder is `testimonial-main`; its source and deployment copies remain unchanged.

## The direction

Build a page that explains PROITBRIDGE through its learners’ progress. A visitor should understand the company, its recorded results, the learning process and a few individual journeys without playing a video or opening a pop-up.

Use three levels of information:

1. **A quick scan:** who PROITBRIDGE is, verified impact, recognizable outcomes and the next step.
2. **A closer read:** short learner stories explaining the starting point, learning experience and result.
3. **Optional depth:** original evidence, longer stories and learner videos.

The visual direction is a human, editorial presentation using PROITBRIDGE’s navy and blue identity. Learner photographs, clear typography and carefully structured content provide the character. Motion helps readers follow relationships and interactions.

### 5. Featured learner stories

Required story structure:

- A short authentic quotation where approved.
- Source/reporting date where relevant.

## Visual design specification

### Identity and composition

Use the existing approved PROITBRIDGE logo. Proposed core palette: deep navy `#102A43`, action blue `#175CD3`, warm white `#FAFAF7`, light blue `#EDF4FA`, body text `#243746`, muted text `#526574`. Check contrast on the final combinations.

Use one restrained heading family and one highly readable body family; suggested direction is Manrope for headings and Inter for body text. Typography and spacing should establish hierarchy before boxes, gradients or decorative elements. These are design choices for review, not a new brand standard.

Desktop: a content width around 1180px, a 12-column grid, 80–104px between main sections, and body copy around 18px with comfortable line spacing. Hero type around 56–64px, section titles around 34–42px. Mobile: 20px side gutters, 48–64px section spacing, body copy 16–18px, hero type around 36–42px. Adjust to the actual copy and available width.

Use a varied reading rhythm: split hero; full-width metrics; aligned outcome rows; numbered journey; portrait-led stories; compact support themes; reviews and videos; quiet closing actions. Avoid repeating a three-card grid throughout the page. Use borders and background changes sparingly. Portrait crops should preserve faces and context. Original evidence is secondary to the readable story, not the card’s dominant visual.

### Visual assets

Needed assets: approved logo; three to six approved learner portraits; accurately cropped video stills; one or two authentic learning/project images where useful; consistent line icons. Existing imagery can be reused after identity, quality and permission checks. Never synthesize a real learner’s likeness, fabricate project work or invent employer affiliations.

Use simple project diagrams or interface crops only when they represent actual learner work and can be understood with a short caption. If suitable imagery is unavailable, use a strong text layout rather than unrelated stock pictures.

### Mobile and navigation

Use a compact header with Results, Stories, Learner Voices and Enquire anchors. Collapse navigation appropriately on small screens. Keep meaningful text visible without horizontal swiping. Stack stories in reading order; use a two-by-two metrics block and a vertical learning journey. A restrained mobile enquiry action may appear after the introduction if it does not obscure content or duplicate the closing CTA unnecessarily.

Make buttons comfortably tappable, preserve keyboard focus, and provide text alternatives for meaningful imagery. Essential reading content must remain available if motion or JavaScript is unavailable.

## Animation and interaction specification

Motion should indicate arrival, relationship or a response to a user action. It should never delay reading. There is no intro gate, mandatory splash screen, scroll hijacking or autoplay media in this proposal.

| Element | Proposed motion | Trigger and timing | Reduced motion |
|---|---|---|---|
| Hero portrait and secondary accent | Small 8px settling movement; headline stays immediately readable | Once on load, about 240ms; no chained delays | Static |
| Section entry | Optional 8–12px settling movement on visual groups, not every text line | Once near viewport entry, 280–360ms | Static |
| Impact numbers | No count-up; values are immediately readable | No numeric animation | Same |
| Journey connector | A short line extends between already-visible steps | Once, 400–500ms; no staged hiding of content | Complete line |
| Background/category selection | Selected state updates, then results settle into place | User click, 160–200ms; preserve focus and context | Immediate update |
| Story detail expansion | Short expansion transition where stable; explicit collapse action | User click, about 200ms | Immediate expansion |
| Buttons and links | Color or underline transition; at most 1–2px movement where helpful | Hover/focus, 120–160ms; touch works without hover | Color/focus state only |
| Evidence viewer | Brief opening transition with close, Escape and focus restoration | User click, 160–200ms | Immediate open |
| Video | Thumbnail changes to player after activation | User click; no background autoplay | Same click requirement |

Avoid animated salary counters, endlessly moving review rows, floating decorative characters, particle backgrounds, parallax photographs and repeated reveal animations. Honor `prefers-reduced-motion`; pause any user-started media when appropriate. Use CSS transforms and opacity for small transitions; a large animation library is not necessary for this direction.

1. Approve the content sequence and wording, including confirmation of program benefits.
2. Confirm whether placement categories mean role families or starting backgrounds.
3. Supply the reporting period, counting definitions and supported organizational metrics.
4. Select three to six stories and complete their factual gaps and permissions.
5. Approve the visual direction and available photo/project assets.
6. Confirm the programs link, enquiry destination and handling process.
7. Select and reconcile the source/build baseline inside `testimonial-main`; the root HTML and current build script do not presently agree.

After these decisions, implementation can preserve the useful sheet-loading, media and story-viewing capabilities while restructuring the page. The first implementation review should check whether a reader can explain the company and its results without watching a video, whether each story has enough information on the page, and whether mobile reading and enquiry work end to end.
